# WeRead Bookshelf — 微信读书书架可视化

把微信读书数据生成为两个可直接打开的本地 HTML 页面，离线可用。页面与数据分离：HTML 是固定模板，更新时只写数据文件，不需要重新生成页面。

- **我的书架**：书架首页，只包含阅读数据，不包含任何划线或想法正文
- **砖墙 · 句子便利贴**：单本书的划线和想法便利贴墙，按需生成

## ✨ 功能特点

- 固定 HTML 模板 + 独立数据文件，无需 Node.js、PowerShell 或本地服务器
- 首页和单本笔记完全分离：打开/更新书架不会拉取划线句子和想法
- 单本便利贴按需拉取，一次只处理一本书
- 封面按 `bookId` 增量更新，已有封面不会重复下载
- 页面与数据均可离线使用

### 📚 我的书架页面

- 扇形封面流（Coverflow 效果）
- 阅读热力图（本月每日阅读时长）
- 阅读进度排行榜
- 阅读偏好分类（环形图）
- 最近在读（含最近一本书的简介）
- 猜你喜欢（个性化推荐）
- 总阅读时长、阅读天数、已读完数量
- 小猫萌宠动画

### 📝 砖 · 句子便利贴页面

- **单本书**的划线和想法做成便利贴墙
- 划线 / 想法切换，两者共用同一套 24 款便利贴样式和排版规则
- 想法便利贴标注所在章节（如“第一章”“导言”）
- 高饱和配色，紧凑瀑布流，多种便利贴形状、图钉、胶带与纸张纹理
- 桌面默认 8 列；1920 大屏（≥1800px）自动切换 10 列，便利贴宽度和间距保持不变
- 可切换莫兰迪 / 高饱和主题（默认高饱和，选择会记住）
- 点击便利贴查看详情（书籍封面、章节、进度、日期）；想法弹窗会显示对应的划线原句
- 单本最多展示 5000 条（划线和想法合计），超出时随机抽样
- 打开前先按概览条数预检；超过 5000 条时提示，不拉取正文、不生成墙
- 小猫萌宠动画

> 全局便利贴墙和跨书搜索已经移除。现在只保留单本便利贴墙，避免书多、笔记多时加载和渲染压力过大。

## 🚀 快速开始

### 1. 前置条件

只需要：

- 微信读书 API Key（环境变量 `WEREAD_API_KEY`）
- 网络

**不需要安装 Node.js、npm、Python、PowerShell 脚本、`weread-skills` 或本地服务器。**

### 2. 配置 API Key

Windows（命令提示符）：

```bat
setx WEREAD_API_KEY "wrk-你的APIKey"
```

macOS / Linux：把下面一行写进 `~/.bashrc` 或 `~/.zshrc`：

```bash
export WEREAD_API_KEY="wrk-你的APIKey"
```

设置后重开终端生效。不要把 key 写进仓库或发到聊天中。

### 3. 安装技能

下载或克隆本仓库，把整个 `weread-bookshelf` 目录放到 agent 的技能目录。常见位置：

- 通用 Agent Skills：`~/.agents/skills/weread-bookshelf`
- Claude Code：`~/.claude/skills/weread-bookshelf`
- Windows：`%USERPROFILE%\.agents\skills\weread-bookshelf`

也可以直接克隆到技能目录：

```bash
git clone https://github.com/LXNNN/weread-bookshelf.git ~/.agents/skills/weread-bookshelf
```

目录中至少要有 `SKILL.md` 和两个 HTML 页面；`data/` 会在第一次更新时自动创建，不需要手动准备。安装后重启 agent，或按所用 agent 的方式重新加载技能。

### 4. 使用

在 agent 对话中直接说：

> 打开书架

agent 会：

1. 调用微信读书 API 获取书架、阅读统计和推荐数据
2. **不拉取任何书的划线或想法**
3. 增量下载缺失封面
4. 写入 `data/shelf.js`
5. 打开 `我的书架-浅色版.html`

想只看某一本书的便利贴墙，说：

> 打开《书名》的便利贴墙

**书名必须用书名号《》包起来。** agent 会只拉取这本书的划线和想法，写入 `data/books/<bookId>.js`，然后打开单本便利贴墙。

想强制刷新某本书的数据：

> 更新《书名》的便利贴墙

说 **“只打开书架，不更新”** 则直接打开现有页面，不调用 API。

## 🧩 它是怎么工作的

两个 HTML 是固定模板，不包含个人数据。

首页通过：

```html
<script src="data/shelf.js"></script>
```

加载书架数据；单本墙通过 `?bookId=` 动态加载：

```html
<script src="data/books/<bookId>.js"></script>
```

更新时只写对应的数据文件，不需要重新生成 HTML，也不需要任何构建工具。

首次使用或数据文件缺失时，页面会显示提示，而不会白屏。

### 首页更新

首页只调用：

- `/shelf/sync`：书架列表、最近阅读时间、已读完状态
- `/book/info`：只取最近在读那一本的简介，用于“最近在读”卡片
- `/user/notebooks`：有笔记的书目概览和阅读进度（**不拉正文**）
- `/readdata/detail`：热力图、偏好、阅读统计
- `/book/recommend`：猜你喜欢
- 封面：只下载缺失项，最多 4 张并发

不再逐本请求划线、想法、章节或进度。首页展示全部书架书，不设置数量上限。

### 单本便利贴更新

打开或更新前先做条数预检：读取 `/user/notebooks` 概览里的 `noteCount + reviewCount`（优先复用 `data/shelf.js` 中的缓存）。合计超过 5000 条时只提示数量，不拉取正文，也不生成便利贴墙；≤5000 条才调用：

- `/book/bookmarklist`：这本书的划线
- `/review/list/mine`：这本书的想法/点评
- 封面：本地缺失时按需下载

5000 是划线和想法的**合计上限**；超出时随机抽样，页面会标注“原书共 N 条，单本仅展示 M 条”。单本墙刷新页面不会重新抽样，只有执行“更新《书名》的便利贴墙”才会重新抽样。

### 更新速度

更新使用 3 路 API 请求池：独立接口同时启动，每个请求启动间隔约 200ms，避免触发限流。

- 首页：约 6–8 个 API 请求，通常几秒完成；封面首次补齐会慢一些。
- 单本：先预检概览；≤5000 条时再请求划线 1 个 + 想法 1–N 个分页，通常几秒；>5000 条时直接提示，不拉正文。
- 单本划线特别多时，`/book/bookmarklist` 一次返回全书划线，首次打开可能明显变慢；这是接口不支持分页导致的已知限制。

### 封面增量更新

封面统一按 `bookId` 命名（如 `data/covers/935536.jpg`），书架和推荐共用同一份文件。每次更新时：

1. 先扫描 `data/covers/`，已有且非空的封面直接复用，不重新下载。
2. 只下载本地没有的新书封面；下载失败会保留远程 URL，下次只重试缺失项。
3. 旧版数据里的封面路径如果指向仍然存在的本地文件，会复用并尽量重命名为 `<bookId>.<ext>`。
4. `shelf.js` 写入成功后，删除已经从书架消失、且没有被推荐或单本数据引用的封面。
5. `shelf.js` 写入失败时不会删除任何封面，避免破坏上一版可用数据。

推荐列表会轮换，因此推荐书的封面可能有少量新增和清理；书架封面仍严格按 `bookId` 增量复用。

## 📁 目录结构

```text
weread-bookshelf/
├── README.md
├── SKILL.md                    # 给 agent 的接口与更新说明
├── 我的书架-浅色版.html         # 首页固定页面
├── 砖墙-便利贴.html             # 单本便利贴固定模板
└── data/                       # 个人数据（git 忽略）
    ├── shelf.js                # 首页运行时数据
    ├── books/
    │   └── <bookId>.js         # 单本笔记数据，按需生成
    ├── covers/                 # 本地封面
    └── title_mapping.json      # 可选：拼音书名映射
```

页面必须和 `data/` 目录放在一起。只复制 HTML 会没有数据、没有封面。

## ❓ 常见问题

**Q: 首页显示“还没有书架数据”？**  
A: `data/shelf.js` 没有加载到。确认 HTML 和 `data/` 在同一目录，并且文件内容是合法的 `window.WEREAD_SHELF = {...};`。

**Q: 单本墙显示“缺少书籍参数”？**  
A: URL 里没有 `bookId`。请通过 agent 打开：

```text
打开《书名》的便利贴墙
```

**Q: 单本墙显示“还没有这本书的便利贴数据”？**  
A: `data/books/<bookId>.js` 还不存在。请对 agent 说：

```text
更新《书名》的便利贴墙
```

**Q: Windows 打开单本墙时提示“找不到文件 ...?bookId=...”？**  
A: 这是把带查询参数的路径直接交给 `start` 导致的。正确做法是用浏览器可执行文件打开 `file:///...砖墙-便利贴.html?bookId=...`，不要把 `?bookId=` 拼在 Windows 文件路径后面。

**Q: 单本超过 5000 条会怎样？**  
A: 5000 是划线和想法的合计上限。打开或更新前会先读取 `/user/notebooks` 的 `noteCount + reviewCount`（优先用 `data/shelf.js` 缓存）；超过 5000 条时只提示数量，不拉取正文、不生成便利贴墙。确认仍要查看时，说「仍然生成《书名》的便利贴墙」，会拉取后随机展示 5000 条。

**Q: 书名为什么必须用《》？**  
A: 这是本技能约定的命令格式，用来避免 agent 把普通对话误判成打开某本书。没有书名号时会提示正确格式，不会擅自搜索书城。

**Q: 为什么没有全局便利贴墙和搜索？**  
A: 全局墙需要把所有书的笔记汇总到同一个页面，书多、笔记多时会带来数据文件和渲染压力。现在首页只负责书架和阅读数据，单本便利贴墙按需生成。单本墙内用“划线/想法”切换，不做跨书搜索。

**Q: 封面不显示？**  
A: 检查 `data/covers/` 下是否有对应图片；如果某张封面下载失败，页面会回退到远程 URL，需要联网才能看到。下次更新只会重试缺失的封面。

**Q: 导入的书显示拼音书名？**  
A: 在 `data/title_mapping.json` 中配置：

```json
{
  "拼音书名": "中文书名"
}
```

然后让 agent 重新更新数据。

**Q: 可以在 Mac/Linux 上使用吗？**  
A: 可以。取数用 `curl` 或 agent 的 HTTP 工具，页面是静态 HTML，不需要 Node 或 PowerShell。

**Q: 为什么没有定时自动更新？**  
A: 本技能按“对话中触发”设计，不注册系统计划任务。需要刷新时说“更新书架”或“更新《书名》的便利贴墙”。

## 📄 数据来源

通过微信读书 Agent API Gateway 获取：

### 首页

- `/shelf/sync` — 书架书籍列表、最近阅读时间、已读完状态
- `/book/info` — 最近在读那一本书的简介
- `/user/notebooks` — 有笔记的书籍概览和阅读进度（不拉正文）
- `/readdata/detail` — 阅读统计和偏好
- `/book/recommend` — 推荐好书

### 单本便利贴

- `/book/bookmarklist` — 单本划线内容，回包同时提供章节标题
- `/review/list/mine` — 单本想法/点评

接口参数、分页和字段说明见 `SKILL.md`。
